---
title: "APM spike — 2026-10-27"
description: "What APM 0.35.0 does for kalfa's distribution, proven in a throwaway HOME and repository, and what kalfa must do itself."
type: log
---

The spike ran APM **0.35.0** (`apm-cli` from PyPI) against a throwaway `HOME`
whose `~/.claude/settings.json` held foreign hooks, a status line and other
keys, and against a throwaway git repository. The real user configuration was
never touched. Claude Code was 2.1.311.

**Install path.** The APM release binary does not start on Ubuntu 22.04: its
bundled Python needs glibc 2.38 and the system has 2.35. The PyPI package runs on
Python 3.10. kalfa therefore installs APM through a Python installer, pinned.

**User-scope skills: proven.** `apm install -g <owner/repo/path>#<commit>`
copies the skill into `~/.claude/skills/`, and `~/.apm/apm.lock.yaml` records the
resolved commit and a sha256 per deployed file. Other settings stay unchanged.

**Hook merge: proven.** A package's `hooks/hooks.json` is appended after the
existing hooks of the same events; foreign hooks, the status line and unrelated
keys stay. `${PLUGIN_ROOT}` resolves to the deployed copy of the package. APM
keeps ownership in a sidecar `apm-hooks.json`, so the merged settings hold only
native fields. APM adds `matcher: "*"` to a `SessionStart` entry.

**Uninstall: proven, with one caveat.** `apm uninstall -g <package>` removes the
skills, the hook scripts, the sidecar and the merged entries. The settings file
keeps the same content, but APM rewrites its formatting, so it is not byte-equal
afterwards.

**Overlays: kalfa's job.** When the upstream skill and a local package with the
same skill name are both installed, APM warns "last installed wins", and a later
plain `apm install` restores the upstream copy: the overlay is lost. When only
the composed package is installed, it survives reinstalls. So `kalfa build`
fetches the upstream skill at its pinned commit, appends the overlay, records
the upstream commit and hash itself, and APM installs only the composed package.

**Scoped rules: proven, and better than planned.** An instruction with
`applyTo: "core/**/*.yaml"` installs for Claude as `.claude/rules/<name>.md`
with `paths:` set to the same glob. `apm compile --target codex` writes a
nested `core/AGENTS.md` and leaves the hand-written root `AGENTS.md` untouched,
so no marked block in the root file is needed.

**Project state lands in the repository.** A project-scope install writes
`apm.yml` and `apm.lock.yaml` at the repository root and adds `apm_modules/` to
`.gitignore`. The repository should hold only `kalfa.yaml`, so `kalfa build`
keeps APM's project state outside it.

**Claude Code and `AGENTS.md`.** With tools turned off, Claude Code reads a
repository's `AGENTS.md` when there is no `CLAUDE.md`; a control run without the
file found nothing. When a `CLAUDE.md` exists, `AGENTS.md` is not read unless
`CLAUDE.md` imports it with `@AGENTS.md`. The bridge is needed exactly in the
repositories that have Claude-only lines.
